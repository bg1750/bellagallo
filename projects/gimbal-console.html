Pan-Tilt Gimbal Control Console

A desktop operator console for a two-axis camera platform, built in Python and PyQt6. It has live attitude instruments, pan, tilt, and zoom controls, connection monitoring for each subsystem, and a latching emergency stop. A built-in simulator drives everything, so it runs end to end with no hardware attached.

Some of my professional work can't be shown publicly, so I built this as a stand-in. It uses the same design patterns and interface techniques I developed on the job, applied to a neutral example and wired to a software simulator instead of real hardware.

This is a self-contained operator console for a two axis camera gimbal, the kind of pan/tilt platform used for tracking and remote observation. I built it to show the kind of control interface I've worked on professionally, in cases where the actual product can't be shared. The layout, the live instrumentation, the status and safety model, and the look and feel all carry over. The only difference is that the device behind it is a software simulator I wrote. Anyone can run it and watch the platform come online, the horizon start moving, and every control respond.

Live Instrumentation

The two main instruments are an artificial horizon and a heading compass, both drawn from scratch with Qt's painter, so the app carries no image assets at all. The horizon shows a pitch ladder and roll scale that track the platform's live attitude, and the compass card rotates to show the pan heading with a digital readout. Both repaint on a 20 Hz loop without blocking the UI thread, so the interface stays smooth while telemetry streams in.

Command Dispatch

You drive the platform through grouped controls: a slew rate "gear" that scales motion speed, momentary pan jogs that move the axis only while held, a type to set tilt angle that eases smoothly to its target, and a motorized zoom stage with a live position percentage. Every command is validated and shown back in the readouts right away.

Status & Safety

A connection status panel tracks five subsystems on their own, and any that drop offline blink so faults are easy to spot. A latching emergency stop freezes all motion instantly, flashes a status banner, and locks out commands until you reset it, the way a real field console handles operator safety.

Architecture

The interface and the device are kept cleanly separate. The GUI only ever talks to a small simulator surface (connect, set angle, jog, toggle zoom, e-stop, step), so the same console could run real hardware by swapping the simulator for a serial or fieldbus backend with the same methods. The UI would not change.
